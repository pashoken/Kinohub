# Как KinoHub ранжирует раздачи

После нажатия «Смотреть сейчас» KinoHub получает варианты из Jackett, анализирует названия раздач и показывает наиболее подходящие сверху.

Вся логика находится в [apps/server/src/release-ranking.ts](../apps/server/src/release-ranking.ts):

- `parseReleaseTitle` распознаёт качество, кодек, языки и другие признаки;
- `rankRelease` начисляет баллы раздачам фильмов;
- `releaseSeasonCoverage` определяет номера сезонов;
- `rankSeriesRelease` добавляет правила сериалов;
- `toPublicChoice` передаёт результат в TV-интерфейс.

Сортировка вызывается в [apps/server/src/app.ts](../apps/server/src/app.ts): сначала варианты идут по убыванию итогового балла, а при равенстве — по названию с русской локалью.

## Что распознаётся в названии

KinoHub пытается определить:

- разрешение: `2160p`, `4K`, `UHD`, `1080p`, `720p`;
- кодек: `H.264`, `x264`, `AVC`, `H.265`, `x265`, `HEVC`;
- диапазон: `SDR`, `HDR`, `HDR10`, `Dolby Vision`, `DoVi`, `DV`;
- источник: `WEB-DL`, `Blu-ray`, `BDRip`, `WEBRip`, `HDTV`, `CAM`, `TS`;
- языки по меткам `RUS`, `Russian`, `РУС`, `ENG`, `English`;
- явно указанную оригинальную английскую дорожку;
- русские и английские субтитры;
- `Remux`, `10-bit` и специальные редакции;
- количество сидов, размер файла и сезоны сериала.

Распознавание основано на названии раздачи. Если индексатор не указал язык или качество, KinoHub не может определить их по содержимому файла.

## Таблица баллов

| Признак | Баллы |
|---|---:|
| 1080p | +45 |
| 720p | +10 |
| H.264/x264/AVC | +35 |
| H.265/x265/HEVC | −10 |
| SDR | +15 |
| Сиды | от 0 до +20 |
| Явно указанная оригинальная английская дорожка | +20 |
| Английские субтитры | +10 |
| Размер больше 12 ГБ | −15 |

Бонус за сиды растёт логарифмически и ограничен 20 баллами. Поэтому живая раздача поднимается выше, но тысячи сидов не могут бесконечно увеличивать её оценку.

В интерфейсе рядом с вариантом показываются причины начисления баллов. Например:

```text
+45 за 1080p
+35 за H.264/x264
+15 за SDR
+16 за сиды
```

## Русская или оригинальная дорожка

Текущая формула создавалась с приоритетом оригинальной звуковой дорожки. Поэтому явно указанная оригинальная английская дорожка получает `+20`, а английские субтитры — ещё `+10`.

Русская дорожка распознаётся и показывается флагом `RU`, но отдельного бонуса по умолчанию не получает. Это не универсальное предпочтение — формулу можно изменить.

Чтобы русская озвучка получала приоритет, откройте `apps/server/src/release-ranking.ts`, найдите функцию `rankRelease` и добавьте рядом с языковыми правилами:

```ts
if (parsed.languages.includes('RU')) {
  score += 20;
  rationale.push('+20 за русскую дорожку');
}
```

Если оригинальная дорожка не нужна, удалите или уменьшите этот блок:

```ts
if (parsed.englishAudio) {
  score += 20;
  rationale.push('+20 за оригинальную английскую дорожку');
}
```

Можно оставить оба бонуса: тогда наверху чаще будут раздачи с несколькими звуковыми дорожками.

После изменения выполните:

```bash
npm test
docker compose -f compose.full.yaml --profile full up -d --build
```

## Несовместимые варианты

Раздача получает балл `−1000` и статус `incompatible`, если обнаружено:

- 2160p/4K/UHD;
- HDR или Dolby Vision;
- Remux;
- CAM/TS;
- 10-bit.

Эта политика рассчитана на предсказуемое воспроизведение на телевизорах и проекторах. Kodi и современное оборудование могут поддерживать часть этих форматов. Ограничения находятся в начале функции `rankRelease` и при необходимости могут быть удалены.

Статус `compatible` получают варианты, где одновременно распознаны 1080p и H.264. Остальные не запрещённые варианты получают `warning`.

## Дополнительные баллы сериалов

После обычной формулы KinoHub проверяет, содержит ли раздача выбранный сезон.

| Условие | Баллы |
|---|---:|
| Раздача содержит выбранный сезон | +12 |
| Пак содержит выбранный и другие сезоны | +30 |
| Раздача явно не содержит выбранный сезон | −300 |
| Сезон невозможно определить | без изменения, показывается пояснение |

Распознаются названия вроде `S01`, `S01-S05`, `сезон 1` и `сезоны 1-5`.

## Как безопасно изменить формулу

1. Измените коэффициенты в `apps/server/src/release-ranking.ts`.
2. Обновите проверки в `apps/server/src/release-ranking.test.ts`.
3. Запустите:

```bash
npm run typecheck
npm run lint
npm test
npm run build
```

4. Пересоберите Docker-стек.

Не удаляйте строки `rationale`: они объясняют пользователю, почему вариант поднялся или опустился в списке.
