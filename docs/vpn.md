# VPN и сетевой доступ KinoHub

KinoHub не требует VPN сам по себе. Однако часть внешних ресурсов может быть недоступна у конкретного провайдера, в регионе или в используемой сети. Это может затронуть:

- Seerr — получение каталога и изображений из TMDB;
- Jackett — обращение к добавленным индексаторам;
- TorrServer — получение данных выбранной раздачи;
- Docker — загрузку образов из Docker Hub и GitHub Container Registry;
- сервер — загрузку исходников и обновлений с GitHub.

Доступность меняется со временем и отличается у провайдеров. Сначала определите, какой именно компонент не работает, и только после этого добавляйте VPN.

Используйте VPN с учётом правил вашего провайдера, условий внешних сервисов и применимого законодательства.

## Где должен работать VPN

Для полного Docker-стека VPN нужен на одном из двух уровней:

1. **На домашнем роутере** — самый понятный вариант. Роутер направляет внешний трафик сервера через VPN, а домашняя сеть продолжает работать напрямую.
2. **На сервере с Docker** — подходит, если роутер не поддерживает VPN. Нужно разрешить локальные подсети в split tunneling или исключениях VPN-клиента.

VPN только на Android TV не меняет маршрут контейнеров Seerr и Jackett, поэтому обычно не решает проблемы каталога или поиска раздач.

## Рекомендуемая схема

```text
Телевизор ── домашняя сеть ──> KinoHub :4100
Телевизор ── домашняя сеть ──> TorrServer :8090
                                  │
Сервер Docker ── VPN ─────────────┴──> внешние API и индексаторы
```

Локальный трафик между телевизором и сервером не должен идти через VPN. Через VPN направляется только внешний трафик сервера.

## Какие адреса оставить локальными

В `.env` по-прежнему указывайте обычный IP сервера в домашней сети:

```dotenv
PUBLIC_APP_ORIGIN=http://192.168.1.50:4100
PUBLIC_TORRSERVER_URL=http://192.168.1.50:8090
LAN_BIND=0.0.0.0
```

Не подставляйте сюда IP VPN-сервера, публичный IP или адрес виртуального VPN-интерфейса.

В настройках VPN разрешите прямой доступ к:

- LAN IP самого сервера;
- подсети роутера, например `192.168.0.0/16`, `10.0.0.0/8` или вашей более узкой домашней подсети;
- `localhost` и `127.0.0.0/8`;
- внутренней Docker-сети `kinohub-stack`.

Конкретное название настройки зависит от клиента: **Allow LAN**, **Local network sharing**, **Bypass local network** или **Split tunneling**.

## Вариант 1. VPN на роутере

Это предпочтительный вариант для домашней установки:

1. настройте WireGuard, OpenVPN или другой поддерживаемый роутером протокол;
2. направьте через VPN только устройство с Docker либо только необходимый внешний трафик;
3. исключите домашнюю подсеть из VPN-маршрута;
4. перезапустите контейнеры;
5. проверьте KinoHub с телефона по Wi-Fi.

Если после включения VPN перестали открываться `http://IP_СЕРВЕРА:4100` и `http://IP_СЕРВЕРА:8090`, проблема находится в маршрутизации локальной сети, а не в KinoHub.

## Вариант 2. VPN на Windows или macOS с Docker Desktop

Сначала подключите VPN на компьютере, затем перезапустите Docker Desktop и контейнеры:

```powershell
docker compose -f compose.full.yaml --profile full restart
```

Docker Desktop умеет направлять контейнерный трафик через сетевой стек хоста, но совместимость зависит от VPN-клиента. Это соответствует [официальной документации Docker Desktop](https://docs.docker.com/desktop/features/networking/networking-how-tos/#working-with-vpns).

Обязательно включите в VPN-клиенте доступ к локальной сети. После подключения повторно откройте KinoHub с телефона: некоторые VPN-клиенты включают kill switch, который блокирует входящие подключения из LAN.

## Вариант 3. VPN на Linux-сервере

Подключите VPN штатным клиентом WireGuard/OpenVPN или приложением своего VPN-провайдера. Не заменяйте сетевой режим контейнеров на `network_mode: host`: KinoHub использует собственную Docker-сеть и имена `seerr`, `jackett`, `torrserver`, `jellyfin`.

Проверьте три условия:

1. исходящий трафик Docker проходит через нужный маршрут;
2. домашняя подсеть исключена из туннеля;
3. firewall разрешает вход из LAN на TCP-порты `4100` и `8090`.

Если включён kill switch, добавьте разрешающие правила для домашней подсети до его активации. Синтаксис правил зависит от VPN-клиента и firewall, поэтому универсальную команду безопасно дать нельзя.

## VPN и HTTP-прокси — не одно и то же

Настройка прокси Docker daemon помогает Docker скачивать образы, но не гарантирует, что все уже запущенные приложения автоматически используют этот прокси.

- Для Docker Engine параметры daemon proxy описаны в [официальной документации Docker](https://docs.docker.com/engine/daemon/proxy/).
- В Docker Desktop прокси настраивается через интерфейс Docker Desktop, а не через `daemon.json`.
- `HTTP_PROXY` и `HTTPS_PROXY` нельзя без проверки добавлять сразу всему Compose: разные приложения поддерживают их по-разному.

Если VPN-провайдер выдаёт только SOCKS/HTTP-прокси, потребуется отдельная настройка каждого сервиса. Для обычного пользователя надёжнее VPN на роутере или уровне операционной системы сервера.

## Пошаговая диагностика

### 1. Проверить загрузку Docker-образов

```bash
docker pull ghcr.io/seerr-team/seerr:latest
```

Если команда не работает, проблема возникает до запуска KinoHub: настройте VPN или прокси для Docker.

### 2. Проверить доступ Seerr к TMDB

Откройте Seerr. Если интерфейс работает, но каталог и постеры не загружаются, проверьте журнал:

```bash
docker compose -f compose.full.yaml --profile full logs --tail=100 seerr
```

Официальная диагностика Seerr отдельно рекомендует проверять доступ контейнера к `api.themoviedb.org`: [Seerr Troubleshooting](https://docs.seerr.dev/troubleshooting/).

### 3. Проверить Jackett

Откройте Jackett и нажмите **Test** у конкретного индексатора. Это точнее общей проверки интернета: один индексатор может работать, а другой — нет.

```bash
docker compose -f compose.full.yaml --profile full logs --tail=100 jackett
```

### 4. Проверить локальный доступ после включения VPN

С телефона в домашнем Wi-Fi откройте:

- `http://IP_СЕРВЕРА:4100`;
- `http://IP_СЕРВЕРА:8090`.

Если до VPN адреса открывались, а после перестали, включите **Allow LAN** или добавьте домашнюю подсеть в исключения туннеля.

### 5. Перезапустить сервисы после смены маршрута

```bash
docker compose -f compose.full.yaml --profile full restart
docker compose -f compose.full.yaml --profile full ps
```

## Что не следует делать

- не устанавливайте VPN только на телевизор в надежде исправить Seerr или Jackett;
- не публикуйте TorrServer и административные панели в интернет;
- не записывайте VPN-логин, пароль или приватный ключ в Git;
- не вставляйте VPN-секреты в `.env` KinoHub — проект их не использует;
- не отключайте firewall целиком ради проверки;
- не направляйте домашнюю подсеть через удалённый VPN без необходимости.

## Короткая памятка

Если нужен VPN, используйте такую последовательность:

1. подключить VPN на роутере или сервере;
2. разрешить локальную сеть в VPN-клиенте;
3. оставить LAN IP в `PUBLIC_*`;
4. проверить Docker pull, затем Seerr, затем Jackett;
5. проверить порты `4100` и `8090` с телефона;
6. только после этого подключать Android TV.
